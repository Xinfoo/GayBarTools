# 参考录屏分析与验证范围

资料为仓库 `docs/` 中更新后的 `Example1.mp4`（约 27.22 秒）、`Example2.mp4`（约 46.08 秒）和 `Example3.mp4`（约 15 秒）。这些录屏证明了页面外观与用户点击流程，无法单凭画面确定真实网页 DOM、iframe 层数或服务器的完成判定规则。

## 可以直接观察到的页面行为

- 新版 `Example1` 和 `Example2` 从章节学习页面开始，不再展示个人主页进入课程的过程。构建文档给出的手动登录入口仍是 `i.chaoxing.com`。
- 学习页使用 `mooc1.chaoxing.com/mycourse/studentstudy` 路径，查询参数包含 `chapterId`、`courseId` 等课程标识。示例中的账号标识不作为程序固定值。
- 页头显示“章节详情”，左上有“返回课程”；右侧是课程目录，左侧有当前章节内容。
- `Example1` 中章节标题为“谨防‘培训贷’骗局”。原生形态的视频播放器显示播放按钮、时间、音量、全屏等控件。录屏后段显示 `2:29 / 2:29`，章节上方显示“任务点已完成”。对本次需要处理的视频，软件须等待真实视频完整播放，不能根据录屏被省略的过程实现跳转或伪造结束；已明确标记完成的任务区域按下文规则跳过。
- `Example2` 展示“校园贷？校园害！”章节的静态文档阅读。文档有自己的窄滚动条，页面右侧另有目录滚动区域。用户把文档内部滚动条移到末尾；末页可见页码 `20` 和文档缩放工具栏。这要求滚动课程内容区域，单独滚动顶层页面不能代表阅读完成。
- `Example3` 展示视频播放中的插题。视频播放到插题位置时，整个播放器矩形被深色半透明答题层覆盖；左上是“判断题”、题干和 `A. 对`、`B. 错` 两个单选项，右上显示题量和已答对数量，右下有独立的“提交”按钮。题目层出现时就已有选中的选项，并显示“共 1 题，已答对 1 题”；这些既有状态不能证明当前答题层已经处理完毕，也不能作为跳过提交、直接判定视频结束的依据。
- `Example3` 中用户选择选项、点击播放器内的“提交”后，底部显示绿色“恭喜你，答对了！”，原按钮变成“继续学习”，随后答题层消失、视频继续播放。录屏可确认提交和“继续学习”两个界面状态，但鼠标在恢复前一直停留在按钮上，不能仅凭画面断定恢复是自动触发还是再次点击触发。自动化需等待页面自然恢复，并兼容可见的“继续学习”操作。录屏未展示答错后的提示、重试入口、多选插题或连续多次插题；这些行为不能从该录屏推定。
- 视频或文档处理后，用户下滚到内容区底部，点击右下角蓝色“下一节”。随后当前章节的检测内容出现；这次切换前后地址栏的章节标识和右侧目录高亮没有变化。程序须根据实际新内容及就绪状态判断切换结果。
- 内容切换存在短暂空白：例如 `Example2` 约 23 秒切换后，题目延迟出现。空白画面不能立即判定为无题并再次点击“下一节”。
- 检测区出现多选及判断题，选项以 `A/B/C/D` 字母标记，判断题内容为“对”和“错”，界面依然使用 `A/B` 标记。`Example3` 另展示播放器内的单选插题。
- 检测页下方有“暂时保存”和“提交”。第一次点击“提交”后出现标题“提示”的遮罩弹窗，正文为“确认提交？”，按钮为“取消”和第二个“提交”。因此提交过程有两个真实点击。
- 提交后进入结果视图，展示“我的答案”、得分和对错图标，不能把这些录屏描述为全部答对。页面右下有“上一节”和“下一节”。再次点击“下一节”后进入下一个章节，目录高亮及 URL 章节标识变化：`Example1` 最后进入文档章节，`Example2` 最后进入视频章节。
- 两段更新录屏都展示了进入检测的分支，没有展示“内容完成后直接进入另一个内容页”的分支。新版构建文档明确要求兼容后者：点击“下一节”后重新识别当前页面，只有实际出现检测题时才答题，否则继续处理新的视频或文档。

## 本地演示与自动化回归

`gaybar_tools/demo/` 是随 Python 包分发的本地网页，可用 Python HTTP 服务提供，不依赖账号或 API。演示主页是 `home.html`，章节入口是 `chapter.html?chapterId=1&courseId=demo`。

1. 第一章有双层 iframe 内的 3 秒 WebM 视频。文件由 FFmpeg 的 `testsrc2` 生成，使用浏览器真实解码、播放及 `ended` 事件，不修改播放速度、不 seek、不派发伪造结束事件。
2. 第二章有双层 iframe 内的三页文档，`#document-viewer` 是真正的内部滚动容器，滚动到底才记录完成。
3. 视频或文档完成后启用右下“下一节”，第一次点击只替换同一章节的内部 iframe，外层 URL 和章节标识不变。检测有单选、多选和判断题；选择全部题目、点击“提交”、再点击确认弹窗的“提交”后，显示明确的“提交成功”反馈并再次启用“下一节”，此时才进入下一个章节。
4. `localStorage` 的 `gaybar-demo-metrics` 只记录真实事件与读数，供集成测试核对视频时长、seek 次数、内部滚动位置、选项点击、两次提交和章节切换。它不驱动浏览器自动化，也不替代页面完成判断。

初始本地页面只复现录屏可见的交互形态，iframe 层级、CSS 类和表单结构用于覆盖自动化能力，不能当成真实学习通 DOM 的证据。后续真实 DOM 检查得到的差异及对应回归见下文。

`tests/test_next_page_integration.py` 使用独立的 `demo/next_page.html` 验证连续文档内容后才出现答题页、同 URL 的 DOM 替换、旧内容短暂残留、直接从答题页开始，以及已提交答题页不重复作答。透明隐藏的视频、框架、题目和历史结果不应干扰当前页面识别。流程每次只处理实际到达的一个学习页面，再通过右下“下一节”重新判断后续类型。

用户在 2026-10-16 提供的诊断截图显示，点击“下一节”后已出现五道章节测验题，但程序仍超时报“章节没有变化”。截图不能证明实际 DOM 类名。对应的 `tests/test_retained_video_quiz_integration.py` 覆盖残留的已结束播放器、被折叠或被独立答题视图覆盖的旧播放器、不同题目容器、隐藏原生选项，以及固定页面中需要内部滚动的长题目。是否跳转成功以实际内容变化及就绪状态为准。

## 视频插题回归范围

视频插题使用独立的 `gaybar_tools/demo/video_quiz.html` 本地页面回归，测试位于 `tests/test_video_quiz_integration.py`，覆盖：

- 在等待真实视频播放期间识别播放器内的可见答题层，提取题干和选项，并沿用现有模型答题及输出格式重试流程。
- 通过鼠标选择答案；页面需要提交时点击播放器内的提交按钮，答对后等待答题层消失，或点击可见的“继续学习”再恢复播放。整个过程中不快进、不 seek、不伪造播放完成。
- 覆盖答案已有预选、已答对数量已有记录的情况；只把答题层实际退出和视频状态变化作为本次交互结果，避免因历史记录跳过当前弹题。
- 覆盖嵌套 iframe 中的插题、同一视频后续插题复用题号、普通弹层以及网页自动恢复播放的情况；将播放器内按钮和章节测验的提交操作区分开，防止误点章节提交或提前进入下一节。
- 播放器外、隐藏和兄弟 iframe 的无关题目不会混入视频题目；模型请求期间停止或题目变化时不点击旧答案，页面明确判错时也不会循环提交。

以上为本地回归范围，不表示已经在真实学习通验证所有页面变体。录屏没有提供真实 DOM，测试页面使用的选择器、表单结构与反馈文案只能证明对应本地场景。

### 下方文档被误判为不可见

2026-10-18 的混排页中，上方视频已完成，下方 PDF 未完成。真实结构为章节卡片 → PDF 模块 → `iframe#panView` → 长文档 `BODY`。主页面的 `BODY` 高度固定、`overflow:auto`，实际由窗口滚动；旧算法在窗口下滚后，把移动到负坐标的 `BODY` 当作独立裁剪容器，错误算出正文可见高度为 0。

现在按 [CSS 视口溢出传播规则](https://drafts.csswg.org/css-overflow-3/#overflow-propagation)区分窗口与独立容器：根元素及向视口传播溢出的 `BODY` 使用视口范围，普通容器继续按实际边界裁剪；设置 `contain` 时不套用 `BODY` 传播例外。`tests/test_mixed_document_geometry_integration.py` 覆盖完成视频下方的嵌套 PDF、固定高度外层 `BODY` 随窗口滚动、零高度 PDF 外壳，以及真实裁剪仍阻断阅读。

在独立临时真实会话中，仅将 PDF 外层框架滚入视口，主窗口滚动到 898px；新算法得到 936×544 的正文可见范围，鼠标落点在正文及各层框架的命中检查均通过，同一 DOM 用旧公式复算高度仍为 0。内层阅读位置未变，未发送正文滚轮、播放视频、进入下一节或作答。该检查验证了故障点的几何修复，完整阅读及导航由本地回归验证。

2026-10-18 的静态文档只读检查发现，`.ans-job-icon` 可以完全没有文字或可访问标签。网站 CSS 用所属卡片的 `.ans-job-finished` 类将图标背景从 `job-status-new.png` 切换为 `job-status-new-complete.png`。程序因此也读取该卡片类，并要求存在属于它的可见任务图标；明确的“任务点未完成”标签优先保留待处理。此次真实静态页仍是未完成状态，检查确认了 DOM 与 CSS 规则，未进行真实已完成文档的跳过操作。

程序在每个任务开始前复查状态。已完成区域不重复播放或滚动，也无需等待其未加载的媒体或阅读器；全页都已完成仍进入正常“下一节”导航。静态文档的独立阅读入口和每次滚轮前也检查状态，阅读途中变为完成则结束该区域，无需继续滚到底。已开始播放的视频保持自然结束，不在任务标记中途变为完成时截断播放。完成标记变化及已完成附件的后续加载不作为新页面的证据。
