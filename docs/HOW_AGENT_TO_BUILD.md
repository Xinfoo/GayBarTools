# 项目构建与功能要求

项目名称：GayBarTools
这是一个使用独立浏览器会话的学习通章节助手，实现视频播放、静态文档阅读、视频插题和章节测验的自动化处理。

本文按 2026-10-18 的当前实现更新；安装启动见 [README](../README.md)，页面差异和验证范围见 [VIDEO_NOTES.md](VIDEO_NOTES.md)。

## 软件特征要求

1. 使用 Python 3.11+、Tkinter 和 Playwright 编写。
2. Linux 使用 Chromium 或 Edge，Windows 使用 Chromium、Chrome 或 Edge；支持自动查找或手动指定浏览器路径。
3. 接入 OpenAI 兼容格式的 LLM API，支持按配置发送截图或本机 OCR 识别文本；OCR 为可选项。
4. 使用模拟鼠标移动、点击和滚轮，带有随机落点与操作间隔。具体措施见 [ANTI_DETECTION.md](ANTI_DETECTION.md)，不保证规避平台检测。
5. 使用独立浏览器配置，登录 Cookie 自动保存到项目的 `.runtime/`，也可点击“立即保存登录状态”；下次启动恢复登录状态，失效后由用户重新登录。
6. “开始刷课”在空闲时可点击，点击后检查当前页面；执行任务和关闭窗口期间禁用。

## 软件工作流程

1. 在前端点击“打开浏览器”，启动软件独立的浏览器会话。
2. 用户手动登录学习通，进入任意课程章节，使要处理的页面成为最近打开的页面。
3. 点击“开始刷课”后，根据实际内容识别视频、静态文档或章节答题页；也支持直接从答题页开始。
4. 同一内容页可包含多个视频、多个静态阅读区域或二者混排。先检查各区域自己的任务点标记，跳过明确标为“任务点已完成”的视频和阅读区，其余按页面从上到下逐项处理。完成状态仅关联当前区域，不能用目录或兄弟区域的标记判断；相同地址的独立阅读器分别判断。每项开始前复查状态，结束后检查新增内容，上方未完成附件仍在加载时先等待。
5. 待处理视频通过播放控件正常播放，开始后等待自然结束，不快进、不修改倍速或网站完成标志。识别到新播放器即可进入播放流程，不将媒体来源非空、元数据已加载或本页后续文档全部就绪作为前提。点击播放后最多等待 15 秒启动，期间不重复点击；各任务轮到处理时再检查加载与执行结果。
6. 视频出现单选、多选或判断插题时，调用 LLM 作答，通过播放器内的选项及必要的“提交”“继续学习”恢复播放。既有选中项或“已答对”计数不能作为本次插题已完成的依据。提交后明确答错时，重新截取当前错误界面并发送 API，附带上一轮提交选项和“之前答案错误、请重新处理”的提示，最多额外纠错 5 轮；改选后正常提交，通过后恢复播放。此纠错仅用于视频插题，不用于独立章节测验；原有格式错误重试规则保持不变。
7. 静态文档先定位可见正文及真正的滚动容器，再把鼠标移入正文发送滚轮，检查滚动进度并确认到底；不能用外层页面或课程目录的滚动代替内部阅读。进入阅读及每次滚轮前复查所属任务状态，已完成时立即结束该区域的阅读，无需继续滚到底。
8. 本页所有待处理视频和文档完成后，点击右下角“下一节”；全页任务均已标记完成时直接进入导航流程。等待实际新内容就绪，允许同 URL 下的 iframe 或 DOM 切换，不能把短暂空白当作课程结束。
9. 跳转后重新识别：有实际章节测验题才作答；有视频或文档则继续处理，允许没有配套测验。章节测验开启“答题页自动提交并继续下一节”时，填答、提交并确认成功后继续；关闭时只填答，等待用户手动检查和提交。已提交的测验不重复作答。该开关不影响视频插题的提交和恢复播放。
10. 模型答案只检查输出格式和选项映射，不设置 AI 置信度门槛。格式错误、空答案或输出截断时，重新发送同批题目及原有截图、OCR 内容，最多额外重试 3 次（含首次共 4 次请求），通过后继续自动化。网络或鉴权错误直接报告；格式重试耗尽时停止。
11. 教师尚未创建完成测验时，点击“下一节”可能出现“当前章节还有任务点未完成，是否去完成？”提示。自动模拟点击该可见提示框内的“下一节”，每次跳转仅确认一次，并继续等待真实内容切换；弹框关闭本身不代表跳转成功。
12. 重复以上流程，直到课程结束或达到“学习页面上限”。上限按整页计数：同页多个视频和文档合计 1 页，后续独立答题页另计 1 页。
13. 点击“停止”后中断后续操作并保留浏览器；验证码、登录失效、无法识别内容或不能确认提交结果等情况会报告原因并保存诊断截图。某项失败或停止时，不继续后面的任务或下一节。

## 软件开发要求

1. 开发过程中使用和生成的文件放在项目目录和 `/tmp` 下，依赖安装到项目的 `.venv/`。
2. 不修改用户日常浏览器配置、shell 配置或系统环境，不自动安装系统包。
3. 缺少可用浏览器时，可下载 Chromium 到项目的 `.runtime/browsers/`。
4. 页面适配改动应补充相应的本地回归；测试使用独立临时配置和本地页面，不默认使用真实账号或外部付费 API。真实环境验证按用户授权范围进行。

## 软件运行要求

1. 运行文件和缓存限制在项目目录及 `/tmp` 内，需要持久存储的数据放在项目的 `.runtime/`，包括浏览器配置、Cookie、设置、日志和诊断截图。
2. 浏览器会话与用户日常配置隔离。Linux 使用 bubblewrap 限制写入范围，隔离不可用时停止启动；Windows 使用独立配置及项目内缓存路径，尚未做 Windows 实机验证。
3. API Key 默认不持久保存；用户勾选“记住密钥”后明文保存到本地配置。启用截图或 OCR 作答时，截图或识别文本会发送到用户配置的 API。

## 构建与检查入口

在项目根目录执行：

```sh
python3 scripts/bootstrap.py
./run.sh
```

本地演示、环境检查及回归：

```sh
./run.sh --demo-headless
./run.sh --doctor
.venv/bin/python -B -m unittest discover -s tests -v
```

Windows 使用 `py scripts\bootstrap.py`、`run.bat` 和 `.venv\Scripts\python.exe`。Linux 需已有 Tkinter、可用的 bubblewrap 和浏览器所需系统库；OCR 另需已有 Tesseract 及相应语言数据，具体安装说明见 [README](../README.md)。
