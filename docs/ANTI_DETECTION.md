# 当前反检测与操作拟人化实现

本文按 2026-10-18 的项目代码整理，说明目前实际使用的措施、参数和验证范围。当前实现减少固定坐标、瞬时点击和完全一致的操作节奏，并在处理视频时过滤鼠标移出事件，配合网页原有播放与阅读流程；没有经过真实学习通风控效果验证，不能保证平台无法识别自动化。

## 1. 鼠标与操作节奏

实现集中在 [browser.py](../gaybar_tools/browser.py) 的 `_delay()`、`_move_mouse()`、`_click()` 和 `read_document()`。

| 措施 | 当前实现 | 使用范围与限制 |
| --- | --- | --- |
| 点击前后随机等待 | 每次普通点击前、后分别随机等待，默认各为 **0.35～1.0 秒** | 来自 `action_delay_min`、`action_delay_max` 配置，并非整个流程的所有等待都随机化 |
| 分步曲线移动鼠标 | 按距离分为 **3～18 步**，在线性路径上叠加正弦偏移，每步等待 **8～25 毫秒** | 使用程序记录的上一次鼠标位置；曲线公式固定，步间等待随机，没有真人轨迹训练模型 |
| 随机点击落点 | 横纵坐标分别取目标框宽高的 **35%～65%** 位置 | 落点位于控件中部区域，减少始终点击完全相同坐标的情况 |
| 随机按下持续时间 | `mouse.click()` 的按下至松开间隔为 **65～140 毫秒** | 与点击前后的等待分开计算 |
| 浏览器输入事件 | 使用 Playwright 的 `mouse.move()`、`mouse.click()`、`mouse.wheel()` 操作浏览器 | 常规填答通过点击控件完成，没有通过 JavaScript 直接写入选中状态 |
| 分段滚轮与随机间隔 | 每次向下发送 **650～1000** 的滚轮位移，随后等待 **0.18～0.32 秒** | 当前已使用加快后的滚动参数；实际滚动距离还受页面容器和浏览器行为影响 |

普通播放按钮、选择答案、提交、网页内提交确认按钮和“下一节”都使用 `_click()`。该方法先确认控件可见、可用、能够接收点击，并在必要时滚入视野，再执行随机落点和鼠标输入。同页视频和文档从上到下全部完成后，统一点击右下角“下一节”，再根据实际内容识别后续页面。

这些随机参数各自独立抽取，尚未建立按用户习惯、题目难度或阅读字数调整操作节奏的模型。

**例外：**停止或异常时暂停视频的 `_pause_video_on_stop()` 直接调用 `locator.click()`，用于尽快停止后台播放，没有经过同一套随机移动和等待。浏览器原生提交弹窗由 `_on_dialog()` 调用 `dialog.accept()` 处理，也没有鼠标轨迹。文档不能据此声称所有交互都经过同一套拟人化操作。

## 2. 按页面实际状态完成播放、阅读和提交

以下实现让流程依赖页面状态，其中一部分主要用于减少误操作，而非隐藏自动化特征。

每个区域开始处理前先读取其所属任务点的完成状态，已明确完成的区域跳过播放或滚动，其余保持原有处理流程。此判断读取网站已有标记，不修改任务状态；已经开始播放的视频仍等待自然结束。

### 视频自然播放

`_watch_video()` 通过播放器控件开始播放，读取 `currentTime`、`duration`、`paused`、`ended` 和 `playbackRate` 等状态，等待视频自然结束。

- 不写入播放进度，不跳转到结尾，不设置加速倍速。
- 检测到播放速度偏离 1 倍超过 `0.01` 时停止，要求人工恢复。
- 不派发伪造的播放结束事件，不写入网站任务完成标志。
- 播放状态轮询默认约每 **2 秒**一次，由 `poll_interval` 控制。这是本地状态检查间隔，不是对网站所有网络请求统一限速。

### 鼠标移出导致暂停的兼容

浏览器在页面脚本运行前预注册捕获监听，默认不拦截事件。仅在处理当前视频期间，启用播放器所在框架及其祖先页面的过滤：对 `isTrusted` 为真、`relatedTarget` 为 `null` 的 `mouseout`、`mouseleave`，以及鼠标产生的 `pointerout`、`pointerleave`，停止事件继续传播，避免网站据此暂停视频。普通页内移入移出、触摸及笔的指针事件不在过滤范围；其他标签页和兄弟框架不启用过滤。

控制状态保存在闭包中，通过每会话随机、不可枚举的 Symbol 临时交接给 Python，交接后删除页面上的该属性，减少固定全局标记。没有改写事件注册或派发函数、`isTrusted`、原生媒体方法和页面焦点/可见性状态，也不发送伪造的活动事件。随机 Symbol 在交接前仍可被枚举，这不是不可检测的保证。

每个视频结束、停止或异常时关闭过滤，关闭浏览器时释放控制句柄。原生暂停按钮及插题引起的暂停仍可生效，原有“停止”仍暂停后台播放。这项兼容仅针对上述鼠标边界事件，不拦截 `blur` 或 `visibilitychange`；已加载页面的后补监听也无法先于既有捕获监听。当前本地真实输入回归通过，保存的真实登录会话已过期，因此尚未核对本次学习通播放器的实际监听机制和效果。

### 在正文内部滚动

`read_document()` 先识别真正承载正文的滚动容器，计算嵌套 iframe 的可见范围，再将鼠标移入能够接收滚轮的正文位置，发送分段滚轮。

`_document_pointer()` 使用一组固定候选点，并检查命中元素和遮挡关系；该定位过程不是随机鼠标落点算法。正文定位、避开课程目录、遇到无进展时换点和底部稳定检查主要解决滚错区域、懒加载及误判完成的问题。

程序不直接赋值 `scrollTop` 将正文瞬移到底部。滚动前的 `scroll_into_view_if_needed()` 用于将目标区域带入视野，正文阅读过程仍通过滚轮推进。

### 通过控件提交并确认结果

`apply_answers()` 点击页面选项，并读取最终选中状态；`submit_quiz()` 点击提交和必要的确认按钮，看到明确提交结果后才允许下一节。未确认结果时不会反复提交。已经识别为已提交的测验会跳过重新答题。

视频中途插题使用播放器范围内的单独流程，点击选项及必要的“提交”“继续学习”，确认弹题关闭和视频恢复后再继续观看；视频自然结束后才点击“下一节”。这些操作仍通过鼠标控件完成，不修改播放进度或网站的完成标记。截图识别和格式重试用于识别、处理插题，属于自动化功能与容错逻辑。

这些属于页面交互与重复操作控制。项目没有直接请求学习通的课程完成或答题提交接口来替代页面流程。流程入口见 [workflow.py](../gaybar_tools/workflow.py)。

## 3. 浏览器与登录状态

| 实现 | 当前用途 | 与反检测的关系 |
| --- | --- | --- |
| 默认有窗口的浏览器 | `headless=False`，用户手动登录、进入课程 | 有窗口不等于隐藏自动化；配置和本地演示仍可使用无头模式 |
| 独立持久浏览器配置 | `launch_persistent_context()` 使用 `.runtime/browser-profile/` | 保留本软件会话中的 Cookie、本地存储等，避免每次启动都创建全新配置；不复用用户日常浏览器配置 |
| Cookie 快照恢复 | 项目内 `cookies.json` 自动保存、启动恢复，包含会话 Cookie | 便于继续登录，不负责伪造账号、设备或浏览器身份；服务端登录过期仍需重新登录 |
| Linux 文件系统隔离 | bubblewrap 限制浏览器向项目和 `/tmp` 之外写入文件 | 保护用户环境，不能作为浏览器指纹隐藏或平台风控绕过措施 |

启动时视口固定为 **1440×960**，语言设置固定为 **`zh-CN`**，没有做视口或语言随机轮换。浏览器仍由标准 Playwright 控制。

登录持久化见 [cookies.py](../gaybar_tools/cookies.py)，目录管理见 [paths.py](../gaybar_tools/paths.py)，文件系统隔离见 [isolation.py](../gaybar_tools/isolation.py)。缓存路径、崩溃报告和密钥存储相关启动参数用于运行隔离与兼容性，不应计为已实现的反检测算法。

## 4. 当前没有实现的能力

代码中没有以下实现：

- stealth 插件、`navigator.webdriver` 隐藏或专门移除浏览器自动化启动参数。
- User-Agent 轮换、Canvas / WebGL / 音频等浏览器指纹伪装。
- 代理池、IP 轮换或账号轮换策略。
- 验证码自动破解或绕过安全验证。`_guard()` 遇到验证码、访问频繁、账号异常或登录失效时会停止，交给用户处理。
- 人为控制正确率、故意改错答案或模拟成绩分布。

移除 AI 置信度门槛、答案格式失败后最多额外重试 3 次，是自动化流程的容错逻辑，不属于反检测手段。程序仍根据题目和模型返回的有效选项填答，没有为了“像真人”而故意选择错误答案。

项目也不是“完全无脚本操作”：仍使用 DOM、JavaScript 读取页面结构和状态、在视频处理期间过滤鼠标边界事件，并按配置截图或执行 OCR。
